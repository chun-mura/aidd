# 日本語で書いた issue・PR には「日本語で書くこと」の通知を出さない (#198)

規模: hook 1本 (`hooks/scripts/tool-reminder.sh`) の1つの通知と、その契約テストのため要約形式。

## 1. 背景と目的

`tool-reminder.sh` は PreToolUse で、`gh pr create`・`gh pr edit`・`gh issue create`・`gh issue edit` のたびに、無条件で `JAPANESE_NUDGE` (「GitHub issue/PR のタイトルと本文は日本語で書くこと…既に日本語なら変更不要」) を出す。条件は `group in ("pr", "issue") and action in ("create", "edit")` だけで、書こうとしている文の言語を見ていない。

そのため、日本語で書いた issue・PR でも毎回出る。利用側のセッションでは、読み飛ばされる通知になっていた (retro 2026-11-28 で摩擦点に選ばれた)。2026-11-28 の aidd のセッションでも、日本語の `--body-file` で起票したときに出た。

目的: 渡されたタイトル・本文がすべて日本語だと hook から確かめられるときだけ、通知を出さない。確かめられないときは今までどおり出す。

## 2. スコープ / やらないこと

やる:
- `--title`/`-t`、`--body`/`-b`、`--body-file`/`-F` の値を読み、日本語かどうかを判定する
- `--body "$(cat <<'EOF' … EOF)"` の形 (Claude が PR を作るときによく使う) では、元のコマンドの heredoc の中身で判定する
- 契約テストに、出す・出さないのケースを足す

やらない:
- 通知の文言・ほかの通知 (PR 前のレビュー証跡の警告、重複検索の要求、ラベルの要求) は変えない
- 英語の文を拒否 (deny) しない。通知のままにする
- `gh api` など、ほかの経路での issue・PR の作成は見ない (今も見ていない)

## 3. 判定

新しい関数 `needs_japanese_nudge(args, directory)` が真のときだけ通知を出す。

**集める値** (既存の `option_values` を使う):
- タイトル: `option_values(args, "--title", "-t")`
- 本文の文字列: `option_values(args, "--body", "-b")`
- 本文のファイル: `option_values(args, "--body-file", "-F")`

**日本語の判定**: ひらがな・カタカナ (U+3040–30FF) か CJK 統合漢字 (U+4E00–9FFF) を1文字以上含むか。英語の識別子・コマンド名が混ざっていてもよい (通知の文言も「コード識別子・コマンドは英語のまま」としている)。

**出さない条件** (すべてを満たすとき):
- create: タイトルが1つ以上あり、本文 (文字列かファイル) が1つ以上ある。片方が無いと、gh が対話で聞くか、`--fill` などで hook から見えない文を書く
- edit: タイトルか本文が1つ以上ある。どちらも無い edit (`--add-label` だけなど) は、今までどおり出す (#198 の範囲を広げない)
- 集めた値がすべて読めて、すべてに日本語が入っている

**読めない値** (通知を出す):
- `--body-file -` (stdin)、存在しないファイル、通常ファイルでないもの (FIFO・デバイス・ディレクトリ)、開けないファイル
- `$(`・バッククォートを含み、下の heredoc で解決できない文字列

## 4. 本文ファイルの読み方

- パスは、`simple_commands` が追跡している `directory` (`cd` を反映済み) から解決する。`~` は `expanduser` で展開する (`cd` の扱いと同じ)
- 開く前に `os.stat` で通常ファイルかを確かめ、`os.open(path, O_RDONLY | O_NONBLOCK | O_NOCTTY | O_CLOEXEC)` で開き、`fstat` でもう一度通常ファイルかを確かめてから読む。デバイスを開く副作用 (制御端末の取得など) と、FIFO の open で止まることを避けるため (stat と open の間に差し替えられても、`O_NONBLOCK`・`O_NOCTTY` と後の `fstat` で止まらず、読まない)。シンボリックリンクはたどる (利用者が渡したパスであり、中身を判定に使うだけのため)
- 先頭の 64KiB だけを読み、UTF-8 (`errors="replace"`) として判定する。大きなファイルで遅くならないため
- 読むファイルは1回の判定で3個まで。超えた分は読めない扱い
- 同じコマンドで既に拒否 (`denials`) が出ていれば、ファイルを読まずに通知を出す。応答しないマウント上のファイルで hook が止まると、hook の出力がまるごと失われ、同じ dispatcher の拒否 (既定ブランチへの force push など) も効かなくなるため (起動できない・止まった hook は通す側に倒れる)。日本語の判定は、ほかの判定をすべて終えた後、出力を組み立てる直前に行う
- 読み込み全体に1秒の上限を置く。各ファイルを開く前と各 read の前に経過時間を確かめ、超えたら読めない扱いにする。1回の stat・open・read が止まる場合までは防げないので、上の「拒否が出ていれば読まない」で拒否を守る。そのときは拒否以外の通知 (この通知・レビュー証跡の警告など) が失われる。まれで助言だけなので受け入れる
- 中身は判定にだけ使う。出力・ログ・状態ファイルには出さない (hook の出力は既存の通知の文だけ)
- 例外 (権限・競合で消えたなど) はすべて「読めない」として扱い、通知を出す

## 5. heredoc の本文

`strip_heredocs` は、トークンに分ける前に heredoc の中身を捨てる (コミットメッセージなどをコマンドとして読まないため)。そのため `--body "$(cat <<'EOF'` の値は、`$(cat <<'EOF'` と `)` だけが残る。

- 元のコマンドから「区切り文字 → 中身のリスト」を作る関数 `heredoc_bodies(text)` を足す。行の走査は `strip_heredocs` と同じ規則 (`HEREDOC` 正規表現、区切り文字の行は `strip()` して比べる) にし、走査を共通の関数にまとめる
- `--body` の値に `HEREDOC` が当たれば、当たったすべての区切り文字について、その区切り文字のすべての中身に日本語が入っているときだけ日本語とみなす。同じ区切り文字 (`EOF`) をコミットメッセージと PR 本文で使い回すことがあり、どの中身がどの値に対応するかを確かめないため、黙る側に倒さない
- 区切り文字の中身が見つからなければ、読めない扱い
- 区切り文字を引用符で囲まない heredoc (`<<EOF`) は中身が展開されるので、中身に `$(`・バッククォート・`${` があれば読めない扱い
- オプションは先頭から順に読み、値として使った語をオプションとして読み直さない (`--title "-b日本語"` はタイトルで、本文ではない)
- heredoc で解決できる値の定義: 値から `$(cat <<D` (`<<-`・引用符付きの D を含む) と閉じの `)` を除いたあとに、`$(`・バッククォート・`${` が残らないこと。残れば (`"$(cat <<'EOF' …) $(別のコマンド)"` など) heredoc の判定を使わず、読めない扱いにする

## 6. 脅威と失敗の扱い

- hook は PreToolUse で、モデルが組み立てたコマンドを読む。判定の誤りで起きるのは、通知が出る・出ないだけで、許可・拒否は変えない
- ファイルを読む処理が増える。読むのはモデルが `--body-file` に渡したパスだけで、読んだ中身は外に出さない。hook の書き込み先 (`~/.claude/aidd/`) は変えない
- FIFO・デバイス・巨大ファイル・応答しないマウントへの対策は 4 のとおり
- 判定がどこで失敗しても、通知を出す側に倒す
- この通知は助言で、強制ではない。判定は「確認」ではなく推定で、回避できる。日本語を1文字入れれば英語の本文でも黙り、hook が読んだ後に gh が読むまでにファイルが変わりうる (TOCTOU)。漢字だけの中国語も日本語とみなす。「1文字以上」にしたのは、英語の識別子・コマンドが混ざる日本語の文を誤って通知しないため。どの場合も起きるのは通知が出ないことだけで、許可・拒否は変わらない
- 受け入れるリスク: hook は Bash のサンドボックスの外で動くので、サンドボックスが読みを拒否するファイル (`*secret*` など) を `--body-file` に渡されると、通知の有無から「日本語の文字を含むか」の1ビットが分かる。中身そのものは出さず、読むのは先頭の 64KiB で判定に使うだけなので、拒否パターンの複製は持たない

## 7. テスト (`tests/hook-contract-test.sh`)

出さない:
- create で、日本語の `--title` と `--body`
- create で、日本語の `--title` と、中身が日本語の `--body-file` (相対パス。`cd` を挟む場合も)
- create で、日本語の `--title` と、heredoc の日本語の本文
- edit で、日本語の `--title` だけ

- 英語だけ (既存の `gh issue create --title test` もそのまま)
- タイトルは日本語で、本文は英語
- create で、タイトルだけ
- `--body-file -`
- 存在しないファイル
- FIFO (待たずに返ること)
- heredoc の中身が英語
- 同じ区切り文字の heredoc が2つあり、片方が英語
- `--fill`
- edit で、`--add-label` だけ
