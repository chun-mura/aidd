# 複数の操作をつないだコマンドを拒否したとき、何も実行されていないことを理由に書く (還流 #219)

規模: hook 1本 (`hooks/scripts/tool-reminder.sh`) の拒否の理由の末尾1行と、その契約テストのため要約形式。

## 1. 背景と目的

`tool-reminder.sh` は PreToolUse で、起票前の検索が無い `gh issue create`、作業を失う git 操作、名指しのないステージ、既定ブランチへの force push などを拒否する。Claude Code の PreToolUse の拒否は Bash のコマンド全体に効くので、拒否されたコマンドの中のどの操作も実行されない。

利用側で、本文ファイルを書く操作と `gh issue create --body-file` を `&&` でつないだ1つのコマンドが、起票前の検索が無いとして拒否された。理由の文は検索を求めるだけだったので、エージェントは前半の本文ファイルが作られたと思い込み、検索のあとで同じファイルを使って起票しようとして、ファイルが無いことに気づくまで1回分の手戻りになった (還流 #219。2026-11-28 に macOS 上で、資格情報なしの使い捨て HOME と状態ディレクトリを使い、hook の入出力だけで再現を確かめた)。

目的: 拒否したコマンドが複数の操作をつないでいるときだけ、拒否の理由の末尾に「このコマンドは、つないだ他の操作も含めて何も実行されていない」趣旨の1行を足す。

## 2. スコープ / やらないこと

やる:
- PreToolUse で拒否を返すとき、コマンドが2つ以上の操作からなれば、理由の末尾に1行を足す
- 拒否の種類を問わない (理由は `denials` をまとめて1つにしているので、まとめた後に1回だけ足す)
- 契約テストに、足す・足さない・何も変わらないケースを足す

やらない:
- 拒否の条件・文言・判定は変えない。拒否を弱めない (理由に1行を足すだけで、`permissionDecision` は変えない)
- 単独のコマンドの拒否には足さない (#219 の「その規則で壊れるもの」: 分かりきった文が増える)
- 拒否の無いとき (通知だけ・何も出さない) の出力は変えない
- PostToolUse・PostToolUseFailure は拒否を返さないので対象外
- `write-guard.sh` など他の hook の拒否は対象外 (Write/Edit は1回に1操作)
- 前半を実行してから後半だけ止める、といったコマンドの書き換えはしない

前提: 拒否がコマンド全体を止めるのは Claude Code の PreToolUse の仕様。Cursor の Shell も `harness-adapter.sh` 経由でこの拒否を受け、`beforeShellExecution` の deny はコマンドを実行しない (Cursor の文書による。実測は未確認)。Codex は `apply_patch` だけを `write-guard.sh` に渡すので対象外。

## 3. 判定

**操作の数**: 既存のコマンドの分割をそのまま使う。`simple_commands` の中で行っている「heredoc の本文とコメントを除き、`tokenize` で区切り (`;` `&` `|` `(` `)` 改行、`&&` `||` を含む) ごとに分け、リダイレクトの対象を落とし、`unwrap` でラッパー・代入・キーワードを外す」までを関数に切り出し、空でない単純コマンドの数を数える。切り出した関数 `split_commands` は「unwrap 後の argv のリスト。空は除く。`cd` を含む」を返し、`simple_commands` はそのリストを受け取って `cd` を追跡する (分割の規則を2か所に持たず、計算も1回)。

- `cd` も1つの操作に数える (`cd x && git reset --hard` を拒否したとき、`cd` も実行されていない)。`simple_commands` は `cd` をディレクトリの追跡に使って yield しないが、数には入れる
- 代入だけ (`X=1`)・キーワードだけ・空の区切り (`(git reset --hard)` の括弧) は数えない
- 引用符の中の `&&` やコミットメッセージの中の改行、heredoc の本文は区切りにならない (既存の分割と同じ)
- 2つ以上なら足す。1つなら足さない

**分割できないとき**: 分割は1回だけ計算し、各検査と数えるのとで同じ結果を使う。分割そのものが例外を投げたら、今までどおりどの検査も走らず拒否も出ないので、1行を足す場面は無い。`tokenize` が引用符の不整合で失敗したときの既存の退避 (空白で単語に分ける) は分割できた扱いにする。

**過大に数える場合**: `fi`・`done` などの閉じのキーワードや、引用符で囲まれていない `$(...)` の中身も1つの操作に数えうる。そのとき付くのは真の文 (拒否したのでどの操作も実行されていない) なので、受け入れる。

## 4. 文言

拒否の理由の最後の行に、次の1行を置く (他の拒否の文と同じく `aidd:` で始める):

`aidd: 拒否したので、このコマンドはつないだ他の操作も含めて何も実行されていない (前半で作るはずのファイルなども無い)。拒否の理由を解消してから、必要な操作をすべてやり直すこと。`

## 5. 失敗の扱い・安全

- 判定は入力のコマンド文字列だけを見る。ファイルを読まず、外部コマンドを起動せず、状態ファイルに書かない
- 数える処理の失敗は拒否の結果に影響しない (失敗しても1行を足すだけで、`denials` と `permissionDecision` は数える前に決まっている)
- 出力に足すのは固定の文字列だけで、コマンドの内容を写さない

## 6. テスト (`tests/hook-contract-test.sh`)

足す:
- `printf body > body.md && gh issue create -R owner/repo --title t --body-file body.md` (検索の無いセッション): 拒否、理由に検索の文とこの1行
- `git status; git reset --hard`: 拒否、この1行
- `cd sub && git add -A`: 拒否、この1行 (`cd` も数える)
- 改行でつないだ2行のコマンド
- `cat > body.md <<'EOF'` と、`&&`・`;` を含む本文、`EOF` の次の行の `gh issue create --body-file body.md` (#219 の heredoc 形)

足さない:
- `gh issue create -R owner/repo --title t` だけ: 拒否、この1行は無い
- `git reset --hard` だけ、`rtk git reset --hard` (ラッパーは操作に数えない)、`X=1 git reset --hard`
- `git commit -a -m "a && b"` (拒否、引用符の中は区切りではない)、`git reset --hard # x; y` (コメントの中は区切りではない)、`git reset --hard;`・`git reset --hard &` (末尾の区切り)、`git reset --hard "x` (引用符の不整合)、本文に `&&`・`;` を含む heredoc の `git commit -a -F -`
- 既存の `cd` の追跡のテスト (`cd src && git add ..` など) がそのまま通る

何も変わらない:
- 拒否の無い複数操作のコマンド (`git status && git log`): 出力が空のまま
- 通知だけが出る複数操作のコマンド: `permissionDecision` が無く、この1行も無い
- PostToolUse の複数操作のコマンド: この1行は無い

## 7. レビュー (design-review --security、2026-11-28)

小さい対象なのでメインが直接レビューし、Agent 6 (security-reviewer) を起動した。high なし。mid 2件は refuter に回し、切り出す関数の戻り値の仕様 (反証成立: §3 に書いてあり、`cd` の追跡は既存テストが見ている) は戻り値を明記するだけにし、heredoc 形のテストが無い (反証失敗) は §6 に足した。low のうち、分割を2回計算する (1回にした)、末尾の区切り・引用符の不整合のテスト (足した)、Cursor での前提 (§2 に書いた) を反映した。
