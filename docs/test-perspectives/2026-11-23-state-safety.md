# #118 共有状態と拒否出力のテスト観点

出典: [Issue #118](https://github.com/chun-mura/aidd/issues/118)。main `e5046c6` で、不正なmain-tree状態によりdenyが消えること、保持されたロックで1秒以内に応答しないことを再現した。

| 分類 | 優先度 | 観点 | 検証 |
|---|---|---|---|
| 正常系 | must | 有効な状態では危険操作を拒否し、共有警告は相手ごとに1回、期限切れは除去する | 既存shared-main-treeケースでカバー済み。修復後も再確認 |
| 異常系（ECP） | must | JSON破損・配列・null・数値・不正なtrees/warned/セッション時刻でもdenyが残る | 実dispatcherへ偽イベントを渡すfixture群。時刻にはbool・文字列・負値・NaN・Infinity・巨大整数を含む |
| 境界値（BVA） | must | 有効な時刻0と現在時刻、不正な負値・未来値を区別し、期限切れだけを除く | 修復後の実状態と既存TTLケースを確認 |
| 異常系 | must | 状態dir・lock・一時ファイル・置換先への書込が失敗してもdenyが残る | 各パスを一時領域内の通常ファイル/ディレクトリで塞ぎ、実OSエラーを発生させる |
| 状態遷移・回復 | must | ロック保持中でも有限時間内にdenyを返し、ロック解放後に再記録できる | 自分のfixtureだけにflockを保持。子プロセスを時間制限付きで実行し、解放後に同じ状態を再利用 |
| 並行実行 | must | 同時更新は排他され、修復・更新後に有効JSONを原子的に置換する | 複数セッションの並行hook。警告を返した更新が保持されることと一時ファイル不在を確認。時間切れによる記録省略は許容し、未記録セッションは再実行で記録できることを確認 |
| 回帰 | must | compound commandの後半の拒否・通常通知・issue検索ゲートも失われない | 複数の偽git/gh操作を1イベントで渡し、既存契約テストも全件実行 |
| セキュリティ | must | 状態へプロンプトやコマンド本文を保存せず、実際の破壊操作を実行しない | sentinelを持つ偽イベントと、使い捨てrepo/stateの実ファイルを確認 |
| フレームワーク結合 | must | 実hookのstdin→Python処理→1個の拒否JSONという配線を維持する | mockレスの実dispatcher実行。Linux/macOSの既存CI matrixも実行 |

テストは既存 `tests/hook-contract-test.sh` のBash/Python形式に追加する。HOME・状態・repoはすべて一時領域に置き、ロックとタイムアウト時に停止するPIDはこのテストが作成したものだけに限定する。プロダクトの性能目標は追加しない。

独立レビューでissue-searchの時刻にも同じ欠陥を確認したため、巨大整数・NaN・Infinity等で検索を確認済みにせず、同じcompound内のGit拒否も維持する観点を追加した。実際の検索後に不正な別セッションの記録が除去され、通常の起票ゲートが回復することも確認する。
