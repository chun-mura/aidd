# テスト観点: 日本語で書いた issue・PR には「日本語で書くこと」の通知を出さない (#198)

対象: `docs/superpowers/specs/2026-11-28-japanese-nudge-language-check-design.md`。実装は `hooks/scripts/tool-reminder.sh`、テストは `tests/hook-contract-test.sh` に足す。

## 1. 正常系

| 観点 | 優先度 |
|---|---|
| create で `--title`・`--body` がどちらも日本語なら、通知を出さない | must |
| create で、日本語の `--title` と、中身が日本語の `--body-file` (`cwd` からの相対パス) なら、通知を出さない | must |
| create で、日本語の `--title` と、heredoc (`--body "$(cat <<'EOF' … EOF)"`) の日本語の本文なら、通知を出さない | must |
| edit で、日本語の `--title` だけなら、通知を出さない | should |
| 短い形 (`-t`・`-b`・`-F`) と `--title=…` の形でも、同じに判定する | should |
| `cd <dir> && gh … --body-file rel.md` で、cd 先から相対パスを解決する | should |

## 2. 境界値 (ECP 適用: 日本語を含む / 含まない、読める / 読めない)

| 観点 | 優先度 |
|---|---|
| 英語だけのタイトル・本文なら通知を出す (既存の `gh issue create --title test` を含む) | must (カバー済み: 35行目ほか) |
| タイトルは日本語で、本文が英語なら、通知を出す (すべてのフィールドに日本語が要る) | must |
| create でタイトルだけ (本文が無い) なら、通知を出す | must |
| edit で、タイトルも本文も無い (`--add-label` だけ) なら、通知を出す | should |
| 空の `--body ""` なら、通知を出す | could |
| 本文ファイルの先頭 64KiB に日本語が無く、その後にだけあるなら、通知を出す | could |

## 3. 異常系 (読めない値は通知を出す側に倒す)

| 観点 | 優先度 |
|---|---|
| `--body-file -` (stdin) なら、通知を出す | must |
| 存在しない `--body-file` なら、通知を出す (例外で hook が止まらず、ほかの判定も出る) | must |
| FIFO の `--body-file` なら、待たずに返り、通知を出す | must |
| ディレクトリの `--body-file` なら、通知を出す | should |
| heredoc の中身が英語なら、通知を出す | must |
| 同じ区切り文字の heredoc が2つあり、片方が英語なら、通知を出す | must |
| `--body` が heredoc と別の `$(…)` を併せ持つなら、通知を出す (5 の定義) | must |
| heredoc で解決できない `$(…)`・バッククォートを含む値なら、通知を出す | should |
| `--body-file` が4個以上あれば、4個目以降は読めない扱いになる | could |
| `--fill` (タイトル・本文の指定なし) なら、通知を出す | should |

## 4. 状態遷移

| 観点 | 優先度 |
|---|---|
| 同じコマンドで拒否が出ていれば (`git reset --hard && gh issue create … --body-file 日本語.md`)、ファイルを読まずに通知を出し、拒否も出る | must |

## 5. 回帰

| 観点 | 優先度 |
|---|---|
| 既存テストの多くが、英語のタイトルの `gh pr create`・`gh issue create` で通知が出ることを「hook が最後まで走った」印に使っている (148行目・298行目など)。英語では今までどおり出る | must (カバー済み: 既存テストが通ること) |
| `strip_heredocs` の走査を共通にしても、heredoc の中身をコマンドとして読まない既存の挙動を保つ | must (カバー済み: heredoc 関連の既存テスト) |
| PR 前のレビュー証跡の警告・重複検索の要求・ラベルの要求は、日本語の判定に関係なく出る | should |

## 6. フレームワーク結合

なし。外部ライブラリは使わず、テストは hook を実際に起動するため、mock を使わない経路になる。

## 7. セキュリティ

| 観点 | 優先度 |
|---|---|
| 本文ファイルの中身が hook の出力に出ない (日本語の判定で、秘密を模した文字列が出力に含まれない) | must |
| デバイス (`/dev/zero` など、キャラクタデバイス) の `--body-file` なら、読まずに通知を出し、すぐ返る | should |
| 通常ファイルを指すシンボリックリンクなら、たどって判定する (設計どおり) | could |

負荷・性能テストはスコープ外。読み込みの時間上限 (1秒) が要るかは、必要なら別に計画する。
