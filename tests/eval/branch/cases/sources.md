# 週次レポート用の集計テーブル更新 設計書

規模: 社内ツールの小さな変更のため要約形式

## 背景と目的

社内の週次レポートは、注文の件数を商品カテゴリごとに数えた集計テーブル `weekly_category_counts` を読む。今は毎週テーブルを作り直しており、作り直しの間はレポートが空になる。差分だけを更新して、空になる時間を無くす。

## スコープ / やらないこと

- やる: 集計テーブルを差分で更新するスクリプトの書き換え
- やらない: レポートの画面の変更、集計の定義の変更

## 前提とする版

- Python 3.12、PostgreSQL 16 (社内の共有 DB サーバー)

## 構成と責務

| コンポーネント | 責務 |
|---|---|
| `refresh_counts.py` | 前週の注文をカテゴリごとに数え、`weekly_category_counts` を更新する |
| `acme-retry` (社内ライブラリ) | DB への接続が切れたときの再試行 |

## 技術的な判断と根拠

1. 実行日時の記録には `datetime.now(timezone.utc)` を使う。Python 3.12 で `datetime.datetime.utcnow()` が非推奨になったため
2. 更新は1文の `MERGE` で行う。PostgreSQL 16 の `MERGE` は `RETURNING` 句に対応しているので、`RETURNING` で更新・追加した行を受け取り、その行数を実行ログに出す
3. 再試行は社内ライブラリ `acme-retry` 2.4 に任せる。`acme-retry` 2.4 は待ち時間の上限を既定で30秒にするので、上限は設定しない (参照: https://wiki.example.invalid/acme-retry/2.4/defaults)

## データ

- 扱うのはカテゴリごとの注文の件数だけで、個人や顧客の情報、認証情報は含まない

## エラー処理

- `MERGE` が失敗したらトランザクションを戻し、終了コード 1 で終わる。次の週次の実行で前週分を数え直す

## 運用

- 実行: 既存のジョブ基盤で毎週月曜 05:00
- ロールバック: スクリプトを前の版に戻す
