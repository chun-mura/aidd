# 入社案内文の作成バッチ 設計書

規模: 社内バッチ1本の追加のため要約形式

## 背景と目的

人事担当が、翌週に入社する社員ごとに初週の案内文 (集合場所、持ち物、書類の送り先) を手で書いている。夜間バッチで案内文の下書きを作り、人事担当は確認と送付だけを行うようにする。

## スコープ / やらないこと

- やる: 翌週に入社する社員ごとに案内文の下書きを作り、人事システムの下書き欄に書き込む
- やらない: 案内文の自動送付、入社後の手続き、人事システムの画面の変更

## 構成と責務

| コンポーネント | 責務 |
|---|---|
| `EmployeeReader` | 人事DBの読み取り専用レプリカから、翌週に入社する社員の氏名・社員番号・個人メールアドレス・携帯電話番号・自宅住所・生年月日を読む |
| `PromptBuilder` | 社員1人ごとに下書き用のプロンプトを組み立てる。読んだ項目をすべてそのまま埋め込む |
| `LocalWriterModel` | 同じホストで動くローカル推論の文章生成モデルにプロンプトを渡し、下書きを受け取る (ネットワーク通信なし) |
| `DraftCache` | 再実行時に同じ社員の下書きを作り直さないため、プロンプト全文と下書きを `/var/cache/onboarding-draft/<社員番号>.json` に保存する |
| `DraftWriter` | 下書きを人事DBの `onboarding_drafts` テーブルに書く (書き込み先は既存の下書き欄) |

## 実行

- 同じホストの cron で毎日 02:00 に起動する。画面や API からの呼び出し、手動の入力は無い
- 入力は人事担当が人事システムに登録した社員の情報だけ。処理件数は1日 0〜30人。1人ずつ順に処理する

## データの保存

- `DraftCache` のファイルは削除しない (再実行と後日の問い合わせ対応に使うため)。ファイルの権限は既定 (umask 022) のまま
- 実行ログ: 下書きの内容を後から調べられるよう、各社員について組み立てたプロンプト全文を DEBUG レベルで `/var/log/onboarding-draft/run.log` に出す。本番でも DEBUG を有効にしておく。ログの保管はホストの既定 (logrotate で 52 週)

## エラー処理

- 文章生成モデルがエラーを返した社員は飛ばし、件数をログに出す
- 翌日の実行で、キャッシュに無い社員の下書きを作り直す
- 人事DBへの書き込みに失敗したら、その社員を飛ばし、翌日の実行で作り直す

## 運用

- デプロイ: バッチのスクリプトと cron の設定を追加する。ロールバックは cron の設定の削除
- 監視: 終了コードを既存のジョブ監視に載せる
