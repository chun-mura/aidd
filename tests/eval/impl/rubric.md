# 採点基準: 実装レビューの比較 (同種・異種)

このファイルは `/aidd:eval impl` の採点専用。ケース・正解キーと一緒に人が確認して凍結し (`tests/eval/impl/freeze.sha256`)、凍結の後は変えない。採点の前の照合 (`# eval verify:`) が通るまで、キー (`keys/`) は読まない。この基準は凍結の前に決めたもので、結果を見てから変えない。変える場合は新しい版として凍結し直し、それより前の結果とは比べない。

## 比べるもの

| 方式 | 中身 |
|---|---|
| 同種 (claude) | `claude -p` の新しいセッション。この eval の固定プロンプト (autonomous-review のレビュー・ループ 2 でレビュー担当に渡す範囲: 差分・変更目的・不変条件・懸念点) と、同じ 3 の JSON 契約 |
| 異種 (codex) | `codex exec --sandbox read-only` の新しいセッション。起動のしかたは autonomous-review の主レビューと同じ。プロンプトは同種と同じ |

どちらも、同じ run の同じ `input/` (変更後のスナップショット。Git の履歴なし)・同じプロンプト (`raw/prompt-<case>.md`)・同じキーで採点する。方式の名前はモデルを表さない。モデル・provider は実測した値 (meta) だけを書き、取れなければ「不明」と書く。

## 試行の扱い

- 試行の単位は「ケース × 方式 × 試行番号」。各方式で各ケース3試行以上。「失敗した試行」は最終回答が無い試行 (起動の失敗・エラー・予算の上限・時間の上限)。失敗した試行は、ケース × 方式ごとに2回までやり直してよい。新しい試行番号で行い、失敗した試行も消さずに数と理由を記録し、方式ごとの失敗率を指標と並べて書く。失敗以外の試行 (契約違反を含む) が3に届かない組は「試行不足」と書き、指標を出さない
- 指標の分母は、失敗以外の全試行 (契約違反を含む)。契約違反の試行は、検出・深刻度一致・危険な変更を止めた・対照の正しい通過のどれも満たさなかったものとして数える
- 最終回答が JSON 契約 (autonomous-review のレビュー・ループ 3) どおりにパースできない試行は「契約違反」。中身を読んで採点し直さない (autonomous-review では修正対象にならないため)。コードフェンスで囲んだだけの違反も契約違反に数え、理由を分けて書く
- 指摘のうち、`file` が `input/` に無い・`line` が範囲外のものは「無効な指摘」。採点に使わない (autonomous-review では修正対象にならないため)。件数は別に書く

## 一致の判定

- シード欠陥: 有効な指摘のうち、キーの「一致判定基準」に当たるもの (同じ問題を同じ場所に指摘している。文言の一致ではない) があれば「検出」。深刻度は問わない。1つのシードに複数の指摘が当たっても1件と数える
- 深刻度一致: 検出したシードに当たる指摘の最も重い深刻度が、キーの「期待する深刻度」を満たす
- デコイ: キーのデコイに当たる指摘が blocker / major なら「誤検出 (デコイ)」。minor / nit なら件数だけ書く
- どちらにも当たらない blocker / major の指摘は、`/aidd:eval` の手順4と同じく、キーを渡さない判定エージェント2体で「誤検出 / 判断保留 / 正当」に分ける。2体の判定が割れたもの・誤検出とされたものは、ユーザーが確かめる。minor / nit は件数だけ書く

## 指標 (方式ごと・ケースごとに、試行ごとの値と3試行の最小〜最大を書く。平均だけにしない)

| 指標 | 定義 |
|---|---|
| 契約どおりの試行 | 契約違反・失敗でない試行の数 / 試行数 |
| シード検出 | 検出した試行の数 / 欠陥ありケースの試行数 (シードごと) |
| 深刻度一致 | 深刻度が一致した試行の数 / 検出した試行の数 |
| 危険な変更を止めた | 「危険な変更: yes」のケースで、verdict が `changes_requested` かつシードを blocker / major で指摘した試行の数 / 試行数 |
| 対照の正しい通過 | 対照ケースで、verdict が `approved` かつ blocker / major の指摘が0件 (無効な指摘を除く) の試行の数 / 試行数。判定エージェントとユーザーが「正当」と確定した blocker / major が対照に出た試行は、「対照の欠陥の疑い」として分母から外して件数を別に書き、キーを直すかをユーザーに確かめる (直すなら新しい版として凍結し直す) |
| 誤検出 | 試行ごとの、誤検出 (デコイ) と、判定エージェントで誤検出と確定した blocker / major の件数 |
| 判断保留・正当 | キー外の blocker / major のうち、判断保留・正当と確定した件数 |
| 無効な指摘 | 試行ごとの件数 |
| コスト | 同種は試行ごとの `total_cost_usd` とモデル別のトークン、異種は試行ごとのトークン (USD は実測できなければ「不明」)。採点は判定エージェントのトークン。合計の行は列ごとに既知の分の合計と不明の項目名を書く |

## 提案の作り方 (凍結の前に決めた規則)

この評価は autonomous-review の適格条件を変えない。結果から作るのは提案だけで、適格条件を変えるかは人が決める (#134 など)。提案は次の規則で機械的に作り、規則に無い判断は「人の判断に残す」に入れる。

- **同種で許容できる範囲の候補**: キーの「変更の種類」ごとに決める。ある種類が候補になるのは、同種の方式が、その種類の欠陥ありケースのすべての試行でシードを検出して深刻度が一致し、かつ、すべての対照ケース (種類を問わない) のすべての試行で正しく通過し、全ケースの試行で誤検出が0件だった場合だけ。契約違反の試行が1つでもあれば、どの種類も候補にしない。1試行でも満たさない種類は候補にしない。欠陥ありケースが無い種類 (対照だけの種類) は候補にしない
- **人の判断に残す範囲**: 上の候補に入らない種類すべてと、「危険な変更: yes」のケース (認可など)。危険な変更は、どちらの方式が止めても、autonomous-review のリスク別の最終判定どおり人の判断に残す
- **異種の結果**: 異種が同種より良かったもの・悪かったものを、ケース・試行ごとにどちらも書く。異種だけが検出した・異種だけが誤検出した、を分けて書く
- **一般化しない**: 提案が当てはまるのは、実測したモデル・CLI の版・この5ケース・この固定プロンプトの条件だけ。ほかのモデル・言語・規模の差分に広げない。このケースの `brief.md` は、シードが破る不変条件を明示している。不変条件が書かれていない・間接的にしか書かれていない差分での検出には広げない
- **未測定の項目**: 実測できなかった値 (異種の USD、モデル名、作業ディレクトリの外の読み取りなど) と、そろえきれなかった条件 (下記) を、結果に必ず書く

## そろえきれない条件 (結果に必ず書く)

- 権限: 異種は read-only のサンドボックスでコマンドを実行できる (読み取りは作業ディレクトリの外にも届く)。同種は `--tools Read,Grep,Glob` でコマンドを実行できない
- 設定: どちらも利用者の設定 (同種は `~/.claude/`、異種は `~/.codex/`) を読み込む。中身の違いは記録できる範囲 (init のプラグイン・モデル) で書く
- モデル: 既定のモデルを使う。実測したモデル名だけを書く
- 実際の autonomous-review との違い: `--reviewer claude` は今のセッションでの自己レビューで、ここで測る新しい文脈の `claude -p` ではない。autonomous-review は主レビューの後に観点別レビュー (エラーハンドリング・セキュリティの `/security-review`・横展開) を行うが、この eval は主レビューだけを測る。提案を autonomous-review に当てはめるときは、観点別レビューの分を含まないことを書く
