## 分離の記録

- 準備 (手順1a) と照合 (手順2) はどちらも通った。キーと過去の結果の採点用の読み込みは、照合の後に行った (上の「手順違反の可能性」を除く)
- meta の判定は8試行が「検出なし」、4試行が「汚染の疑い」。中身は次の2つの型で、どちらも compare の型1・型2と同じ。keys・results・元リポジトリへの参照は無い
  - 型1: 実行担当のメインが、自分のセッションが退避した長い tool 出力を Read した (crosscut t1、1件)。パスの session_id はその試行の meta の session_id と一致する
  - 型2: reviewer・security-reviewer の `SubagentHandback` の返却文に、相対パスや `~` の表記があった (data-error t1、crosscut t1・t2・t3)。外のファイルを開いた記録ではない
- 経路の注記: 全12試行で reviewer ×3 → refuter → arbiter の順に進み、ショートカットは使っていない。security と crosscut は全試行で security-reviewer も起動した。crosscut t2 は、実行担当が refuter を2体に分けて起動した (F1〜F24 と F25〜F47)
- 分離の限界: 作業ディレクトリの外の読み取りは権限で禁止していない。Bash のコマンドは検出しきれない。抽出から凍結までの間は書き換えられる (手順の「分離の限界」のとおり)
