# design-review 実行結果（対象 `cases/crosscut.md`、`--depth=deep`）

refuter は、混ぜた指摘3件（M1〜M3）をすべて反証しました。reviewer の high/mid 指摘44件は、1件も反証されずに残りました。arbiter の最終報告は high 6件・mid 13件・low 5行（個別には9件）で、最優先の修正は「利用の残高判定と引き当てから仮付与（pending）を外す（L269-270）」です。

  - 列の削除は、安定稼働を確かめた後の別リリースにする
  - ロールバック手順に、`point_balances.confirmed_balance` から旧列へ書き戻す逆移行を入れる
- D5 の「同じリリースで削除」は見直しが必要。

**裁定3: 項目2・3・4・6 はすべて high とする**

### 4. 最優先で直す1点
**項目2: 利用の残高判定と引き当てから仮付与（pending）を外す（L269-270）。**

選んだ理由は次のとおり。
- 障害時でなく、配送完了から15日間の利用という通常の経路で毎日起きる。
- 用語（L51）・API（L101）・状態遷移（L236）の定義と、返品処理（L311）の前提を同時に壊している。
- ここを直さないと、返品時の回収を正しく設計できない。

修正案は次のとおり。
- L269: 判定を `confirmed_balance >= 要求ポイント` にする。
- L270: 引き当て対象を `status = 'confirmed' AND expires_at >= 当日` に限り、「NULL の仮付与は最後」の記述を削除する。
- L311 の前提は、この修正で初めて成り立つので、そのまま残してよい。

これらは文書上の修正案です。反映する前に、担当者が事実関係と、法務と合意した規約（D2・第12条）との整合を確認する必要があります。
