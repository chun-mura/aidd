### Agent 6 — セキュリティ（aidd:security-reviewer、STRIDE）
1. **high（EoP/ID）** L29・L33：取引先の認可が無く、他社の契約書を取得できる（IDOR）。代案：所属取引先ID と `対象取引先ID` を照合し、不一致なら 404 を返し、監査ログに残す。
2. **mid（ID）** L45：署名付き URL を INFO ログに保存しているため、ログを読める人が 5 分以内なら認証なしで取得できる。代案：記録はオブジェクトキー・有効期限・署名ハッシュなどにとどめ、ログのアクセス制御を明記する。
3. **mid（Repudiation）** L15・L24・L45：監査が足りない。代案：S3 アクセスログまたは CloudTrail を有効にし、監査対象を広げ、書き込み専用の保存先に置く。
   - 記録が URL 発行時だけで、S3 からの実際の取得が残らない
   - アップロードと認可失敗が監査対象に入っていない
   - 改ざん防止が無い
4. **mid（Tampering/Spoofing）** L22・L28・L33：アップロード側で次が書かれていない。代案：CSRF トークン（または SameSite と Origin 検証）、S3 キーはサーバーが生成する UUID にする、取引先ID の検証、ウイルススキャン。
   - CSRF 対策
   - ファイル名の扱い（S3 キーへの使い方、Content-Disposition への注入）
   - 対象取引先ID の存在確認と、アップロードする人の権限検証
   - 能動コンテンツ（JavaScript など）を含む PDF
5. **mid（ID）** L22・L29・L33：S3 の保護が書かれていない。代案：これら 4 項目を明記する。
   - パブリックアクセスブロック
   - SSE-KMS による暗号化
   - 署名に使うロールの最小権限
   - `response-content-disposition=attachment`
6. **low（DoS）**：レート制限・クォータ・同時実行数の上限が無い。
7. **low（Spoofing）**：取引先アカウントの認証強度（MFA・ロックアウトなど）が決まっていない。

## security-reviewer の起動

**yes**

フラグなしで、メインが対象の内容から判定しました。次の 3 点が SKILL.md の起動条件に当たります。
- 取引先（外部）ユーザー向けに公開エンドポイント `GET /api/files/{file_id}` を出している。
- 認証・認可があり、外部からファイルをアップロードできる。
- 秘密情報（署名トークン入りの URL）をログに 90 日保存する。
