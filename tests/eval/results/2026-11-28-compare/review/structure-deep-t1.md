## 経路

- **dispatch した agent**: 1つのメッセージで aidd:reviewer を3体、並列に起動した。
  - Agent 1: 構造
  - Agent 2: データとエラー
  - Agent 3: 実用性
  - 各 agent には対象パス `cases/structure.md` と担当観点だけを渡し、「このファイルだけをレビューする」と明示した。
- **起動しなかった agent**:
  - Agent 4（プロジェクト固有観点）: `.aidd/design-perspectives.md` が無いため起動しなかった。
  - Agent 5（source-verifier）: `--verify-sources` の指定が無いため起動しなかった。
  - Agent 6（security-reviewer）: 条件判定で「該当しない」としたため起動しなかった（理由は最後の節）。
- **refuter**: 起動した（sonnet）。mid が10件あったため。
  - 補足: refuter は2回起動している。1回目は、reviewer の実際の報告が届く前に会話に出ていた結果（実際の報告と内容が違い、正しく届いたものではない）をもとに指摘一覧を渡してしまった。
  - そのため1回目の判定は破棄し、SubagentHandback で届いた実際の報告の指摘で2回目を実行した。下に載せるのは2回目の判定だけ。
- **arbiter**: 起動した（aidd:design-arbiter）。deep 経路では、反証後に high/mid が残ればそれだけで起動条件を満たす。今回は次の2つもあった。
  - S5(low) と D3(mid) の深刻度の食い違い
  - S3 と P4 の依存注入の向きの食い違い
- **小規模対象ショートカット**: 使っていない。対象は1ファイル・62行で条件には当たるが、評価の指示に従った。
- **進めるうえで自分で決めたこと**:
  - `.aidd/review-dismissed.md` が無いので、棄却済み一覧は「なし」として渡した。
  - 独立してマージできる単位は1つだけなので、`/aidd:issue-split` は提案しなかった。

> # 設計レビュー最終報告: 週次利用レポート自動生成機能
>
> 対象: cases/structure.md
>

> class ReportManager:
>     def __init__(self, config: ReportConfig,
>                  renderer: Renderer | None = None,   # test-only override
>                  mailer: Mailer | None = None): ...
>
>     def generate_and_send(self, week_start: date) -> SendResult: ...

## security-reviewer の起動

**no**

この設計は社内ダッシュボードの利用イベントを読み取り専用で集計し、社内の関係者へメールで送る内部バッチ処理です。次のどれにも当たらないため、信頼境界を跨ぐデータフローは無いと判断しました。

- 外部入力: 無い（実行するのは cron と社内の手動 CLI だけ）。
- 認証・認可: 設計の対象に無い。
- 秘密情報: 扱っていない。SMTP は接続済みのクライアントを受け取るだけで、認証情報の扱いは設計に出てこない。
- 外部公開エンドポイント: 無い。

機微情報の保存にも当たりません。キャッシュは行わないと決まっており（L61）、HTML は送信後に破棄し（L44）、ログに出すのは送信件数だけです（L57）。`--security` も `--no-security` も指定されていないので、この条件判定に従いました。
