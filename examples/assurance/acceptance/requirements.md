# 原要件: 架空の経費精算 API

**これは架空のサンプルである。** 実在の組織・人物・業務とは関係ない。説明は [受け入れ基準と重要性質の検証](../../../docs/assurance/acceptance.md) にある。

この文書は、業務責任者 (所有者、架空の「経理部長」) が自分の言葉で書いた要件と、質問への回答 (所有者の判断) である。実装者は書き換えない。受け入れ基準 ([criteria.md](criteria.md)) の期待値は、この文書から導く。実装から写さない。

- 所有者: 経理部長 (架空)
- 版: 2026-11-28 第1版

## 要件

| ID | 原要件 (所有者の言葉) |
|---|---|
| R-1 | 社員は経費を申請できる。1件の金額は1円以上100万円以下の整数 (円) とする |
| R-2 | 申請を承認できるのは、申請者と同じ組織の承認者だけである。自分の申請は承認できない |
| R-3 | 社員は自分の申請だけを見られる。承認者と経理担当は同じ組織の申請を見られる。他の組織の申請は見られない |
| R-4 | 支払いをするのは経理担当で、承認済みの申請だけを支払う。1件の申請には1回だけ支払う。通信の再送やボタンの二度押しで二重に支払ってはならない |
| R-5 | 支払いの途中で送金先とのやり取りが失敗したら、その支払いは無かったことにする。やり直したら1回だけ支払われる |

## 所有者の判断 (質問への回答)

実装の前に、要件の曖昧な点を所有者に質問し、所有者が決めた。

| ID | 質問 | 所有者の判断 |
|---|---|---|
| D-1 | 見られない申請 (他の組織の申請、他人の申請) を開く・承認する・支払うとき、「権限が無い」と返すか、「存在しない」と返すか | 「存在しない」と返す。申請があることも知られたくない。存在しない ID のときと同じ応答にする。見られる申請への許されない操作 (自分の申請の承認など) は「権限が無い」と返す |
| D-2 | 100万円ちょうどは申請できるか | できる。100万1円からはできない |
| D-3 | 同じ再送用の鍵 (idempotency key) で、別の申請の支払いを求められたら | 支払わずに断る (取り違えの疑いがあるため) |
| D-4 | 同じ申請に、別の再送用の鍵で2回目の支払いを求められたら | 2回目は支払わない。1回目の支払いの記録を返す |
| D-5 | 経理担当が他の組織の申請を支払えるか | できない。経理担当も自分の組織だけを扱う |

## 対象外 (この要件が決めないこと)

所有者が「今回は決めない」とした事項。受け入れ基準もこれらを主張しない。

| ID | 対象外の事項 | 理由 |
|---|---|---|
| X-1 | 利用者の認証 (誰がログインしているか) | 認証は別の仕組みが担う。この API は認証済みの利用者 (組織・役割) を受け取る前提 |
| X-2 | 承認の取り消し、差し戻し、部分支払い | 今回の業務の範囲外 |
| X-3 | 税・為替・通貨 | 円だけを扱う |
| X-4 | 性能・同時に大量の要求が来たときの順序、永続化と障害からの復旧 | 今回の範囲外。複数プロセスからの同時実行は別途検証が要る |
| X-5 | 通知・画面 | API だけを対象にする |
